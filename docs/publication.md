# 記事の公開手順

記事は日本語を `src/content/blog/{slug}.md`、英語を `src/content/blog/en/{slug}.md` に配置する。
同じslugと同じ `publishedAt` の日英版を、同じ変更に含めて公開する。
`publishedAt` はタイムゾーンを含むISO 8601文字列で、表記もそろえる。

日本語原稿を作成、更新したら、対応する英語版についてもタイトル、概要、本文、引用、記事間リンクを確認する。
翻訳には `translate-thought-learning-logs` スキルを使い、翻訳と独立したChatGPTレビューで意味、論調、引用、専門用語を確認し、指摘を原文と照合して反映する。
原文の変更時は既存レビューをそのまま流用せず、変更に対応する翻訳とレビューを実施する。
翻訳注釈と原文リンクはテンプレートが生成するため、本文へ重複して書かない。

本文の記事間リンクは、日本語では `/articles/{slug}/`、英語では `/en/articles/{slug}/` を使う。
通常形式と参照形式のMarkdownリンク、およびHTMLのアンカーが検査対象となる。
相対パス、同一サイトの完全URL、Markdown出力URL、末尾スラッシュを省いた形式は使わない。
クエリやフラグメントは付けられるが、参照先の記事と言語は一致させる。
外部サイト、記事以外へのリンクとコード例は記事間リンク検査の対象にならず、見出しIDの存在や外部URLの到達性も検査しない。
テンプレートの言語切替と英語注釈の原文リンクは意図的な言語間参照である。

翻訳、レビューの完了後、`node scripts/test-publication-contract.mjs` と `npm run build` を実行する。
ビルドは全記事の日英ペア、公開日時、本文の記事参照を検査し、違反があれば原因ファイル、対象、理由を示して失敗する。
タイトル、概要、本文、原文リンク、Markdown出力を生成物で確認し、日英版を同じ変更でコミットする。
意味の妥当性やレビュー完了は自動検査では判定できないため、レビュー結果をIssueへ記録する。

日英の画面・検索・切替・一覧復帰・公開案内の回帰確認には `node scripts/test-bilingual.mjs` を使う。
Playwrightが通常のimport先にない場合は `PLAYWRIGHT_MODULE` にインストール済みモジュールのパスを指定する。
このテストは一時ディレクトリの日英11組と専用プレビューで動作し、既存原稿とdistを変更しない。

既存のmain向け公開CIも `npm run build` を実行するため、両言語は同じ配備成果物に含まれる。
検査失敗時は公開せず、前の配備を維持し、原稿を修正する。
検査を解除してロールバックする場合は、日英同時公開の契約が弱まることを記録する。
JP/EN移行期間中はIssue記載のdevelop統合規則に従い、mainへの最終統合、pushには人間の明示承認を得る。
