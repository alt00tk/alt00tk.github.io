# 記事一覧と詳細ページを静的生成する

## 問題

記事の入力契約が整っても、Markdownから記事一覧や個別記事へ移動できるページがなければブログとして閲覧できない。

## 意図

有効なMarkdown記事から、記事一覧と記事詳細を静的に生成し、記事情報を一貫して表示する。

## 受け入れ条件

- [x] / に記事一覧を生成し、各行に東京時間の YYYY.MM.DD、詳細ページへの通常リンクとなる記事タイトル、descriptionを表示する。
- [x] /articles/{slug}/ に記事詳細を生成し、日付、titleをh1見出しとして、descriptionを導入文として、Markdown本文をその後に表示する。
- [x] 一覧と詳細の順序は publishedAt の完全なタイムスタンプ降順で決まり、同じ日の記事も時刻で正しく並ぶ。slugによる同時刻の追加ソートを行わない。
- [x] 一覧と詳細の日付は同じ publishedAt を Asia/Tokyo で YYYY.MM.DD に変換して表示する。
- [x] 一覧ページの文書タイトルは notes とし、マーケティング用の文言を追加しない。詳細ページの文書タイトルは「記事タイトル — notes」、meta descriptionは記事のdescriptionとする。
- [x] 一覧・詳細の文書言語は日本語になる。
- [x] 記事末尾に ← Articles を置き、常に / への通常リンクとして動作する。
- [x] 記事本文で段落、##・###見出し、順序なし・ありリスト、引用、リンク、強調、インラインコード、フェンス付きコードブロックを表示できる。
- [x] 一覧から詳細への移動と記事末尾からの戻りがJavaScript無効時にも動作し、クライアント側ルーターや記事データストアを必要としない。

## 対象外

- 1ページ10件への制限とページ送り（BLOG-003で扱う）
- 試作HTMLに基づく最終的なレイアウト、色、余白、レスポンシブ調整（BLOG-004で扱う）
- Aboutページ、タグ、カテゴリ、検索、関連記事、画像、MDX、記事本文のraw HTMLやテーブル対応
- 記事一覧の空状態に対する仕様外の案内文追加

## 品質境界

ビルド時点で存在する有効な記事を漏れなく一覧と詳細へ反映し、一覧・詳細・戻りリンクを静的HTMLとして提供する。記事の公開状態を追加せず、本文のdescriptionを重複表示しない。

## 実装メモ

- URLの末尾スラッシュを保ち、slugはBLOG-001のファイル名契約に従う。
- 引継ぎ資料と同梱プロトタイプは .local/blog-mvp-codex-handoff.tar.gz 内にある。
- ページ枠と見た目の仕上げはBLOG-004に残し、このIssueではページの意味と遷移、表示データを確認できる最小限の構造を実装する。

## 設計判断

- 決定: 日本語文書言語、タイトル、任意のmeta descriptionを`BaseLayout.astro`にまとめた。一覧は`notes`だけを渡し、記事詳細だけが記事のdescriptionを渡す。重複したhead記述がページ間でずれる案を避け、一覧へ仕様外の説明文を追加しないためである。ページ固有のheadが必要になった場合に再検討する。
- 決定: 記事一覧と詳細ルート生成の両方で`publishedAt`を降順に並べ、同時刻は比較結果0のままにする。schemaが任意桁の秒未満を許すため、ミリ秒より細かい差はISO日時の小数部で比較する。日付表示も共通関数でAsia/Tokyoへ変換する。これは入力契約の精度まで順序を保ち、slugによる追加順序を作らず、両ページの日付を一致させるためである。日付だけで並べる案とslugをtie-breakerに使う案は要件を満たさないため採用しない。
- 決定: 詳細をAstroの静的`getStaticPaths`とContent API `render`で生成し、一覧・戻りは通常の`<a>`リンクにした。本文と遷移をHTMLとして提供するためで、クライアント側ルーターや記事データストアを追加する案はJavaScript無効時の条件に反する。Astroの`trailingSlash: "always"`で末尾スラッシュを保つ。

## 完了記録

- 変更: 共通layoutで日本語文書とページ別metadataを出力し、東京日付の整形、publishedAt降順の記事一覧、静的な記事詳細、本文表示、一覧と戻りの通常リンクを追加した。Astroの末尾スラッシュ設定を`always`にした。
- 検証: `npm ci --offline --cache=/tmp/blog-001-npm-cache`と`npm run build`を実行した。一時的な記事を使ったbuild後のNode.js HTML確認で、詳細ルートと同日内の時刻順・同一ミリ秒内の小数秒順、`+09:00`と`Z`双方の日付が東京時間で同日になること、title/meta/lang、指定Markdown要素、通常リンク、script要素がないことを確認した。一時記事を削除した後も`npm run build`は成功した。`node_modules/.bin/tsc --noEmit`はTypeScript CLIが依存にないため実行できず、検証に含めていない。
- レビュー観点: タイムゾーンoffsetをまたぐpublishedAtの順序と東京日付、記事本文のMarkdown出力、両リンクの通常遷移、生成HTMLにクライアントscriptがないことを確認する。見た目の調整はBLOG-004の範囲に残す。
