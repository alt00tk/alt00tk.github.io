# 既存公開記事の日英版をそろえる

## 問題

既存記事の英語版がそろっていない状態では、日英同時公開の契約を適用できない。開発期間中もmainに日本語記事が追加・更新される。

## 意図

統合対象の既存記事を、原文と意味が対応するレビュー済みの英語記事とともに公開可能にする。

## 受け入れ条件

- [x] 対象mainをdevelopに取り込んだ時点の全日本語記事について、blog/enに同名の英語Markdownを配置する。対象原文を特定できる検証記録を残す。
- [x] 英語のタイトル・概要・本文を翻訳し、slugと公開日時は日本語版に一致させる。翻訳注釈は本文に重複記載せず共通テンプレートに任せる。
- [x] 翻訳にはtranslate-thought-learning-logsスキルを使用し、コンテキストを分離したChatGPTレビューで意味・論調・引用・専門用語を確認する。レビュー結果と修正反映を記録する。ChatGPTレビュー未実施の原稿をレビュー済みとして扱わない。
- [x] 本文の記事間リンクは、日本語では/articles/{slug}/、英語では/en/articles/{slug}/とし、両言語の参照先が存在する。
- [x] ビルド成果物でタイトル・概要・本文・原文リンク・Markdown出力を確認する。後続の検査実装がなくても、今回の内容だけで公開可能な状態にする。

## 対象外

- 翻訳APIやCI自動翻訳の導入
- 原文の主張の改稿
- 翻訳の意味を自動判定する機構
- 日英同時公開契約のビルドへの組み込み（BLOG-024）

## 品質境界

対象原文への忠実さと公開物としてのリンク・メタデータ整合を確認する。最終統合までにmainで追加・変更された記事は統合前に追従し、過去のレビュー記録で新しい原文の確認を代用しない。

## 実装メモ

記事ごとの翻訳・レビューは必要な範囲で順次行い、Issueは既存記事の日英対応を完了する一つの移行として管理する。最終統合時のmain取り込み後に差分があれば、統合を保留して追加・再レビューする。閉じた後に追加の実作業が必要な場合は運用規約に従って後続Issueを起案し、既存Issueを再オープンしない。単独配備の前提はBLOG-021。

- このJP/EN対応では、一時的な `develop` を統合先とする。Issueブランチは最新の `develop` から作成し、Issue IDを含める。各Issueは承認後にclosedの記録を含めて `develop` へ `--no-ff` で統合する。通常運用のmain向け統合規則に対する、今回のユーザー承認済み例外である。
- mainでは日本語記事の執筆・公開を続ける。必要時および最終統合前にmainをdevelopへ取り込み、記事を失わない。Issueの完了はdevelopへの統合を意味し、本番配備済みとは扱わない。
- BLOG-021〜BLOG-024がすべてclosedとなり、最新mainを取り込んだ全記事の日英対応とビルドを再確認してから、人間の明示承認を得てdevelopをmainへ `--no-ff` で統合する。承認済みなのは今回の起案内容のmainへの直接コミットまでで、将来の統合・push承認を含まない。
- 本Issueは依存と記載の前提が満たされれば後続Issueなしでビルド・配備できる状態にする。実際の本番公開は全Issue完了後とし、main向けの既存配備workflowは維持する。

## 設計判断

- 既存の言語別配置と共通テンプレートを利用し、英語Markdownだけを追加する。slug・公開日時・引用URLを保持し、本文の記事間リンクのみ言語別にする。原文は改稿しない。
- 対象mainはdevelopに取り込み済みだったため追加マージは行わず、対象コミットと原文SHA-256を本Issueの完了記録に保存した。
