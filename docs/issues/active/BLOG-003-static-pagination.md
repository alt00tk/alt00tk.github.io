# 記事一覧に静的なページ送りを追加する

## 問題

記事をすべて1ページに出す一覧では、記事数の増加に応じて一覧ページが長くなり、引継ぎ資料で定めた一覧仕様を満たさない。

## 意図

記事一覧を10件単位で分割し、各ページ間を通常の静的リンクで移動できるようにする。

## 受け入れ条件

- [x] 1ページあたり新しい記事から最大10件を表示する。
- [x] 記事総数が10件以下ならページ送りを表示しない。
- [x] 記事総数が11件以上ならページ送りを表示し、現在位置を「現在ページ / 総ページ数」と示す。
- [x] 1ページ目は / のみを生成し、/articles/page/1/ は生成しない。2ページ目以降は /articles/page/2/ の形式で静的生成する。
- [x] 1ページ目では「Newer」を操作不可として表示し、「Older →」は次ページへ移動する。
- [x] 2ページ目以降では「← Newer」が直前ページへ移動し、次ページがある場合のみ「Older →」が次ページへ移動する。最終ページの「Older」は操作不可として表示する。
- [x] 操作できない方向も表示位置を保ち、通常リンクがある方向はJavaScript無効時にも動作する。
- [x] 0件、1件、10件、11件、20件、21件の記事数でページ数・表示件数・先頭／中間／末尾の移動先が仕様どおりになる。

## 対象外

- ページ番号のリンク一覧やクライアント側ページ切り替え
- 1ページ10件以外の設定画面・利用者向けカスタマイズ
- ページ送りの最終的な色、余白、モバイル表示調整（BLOG-004で扱う）

## 品質境界

記事総数の境界で記事の欠落・重複・空の余分なページを発生させず、要求されたページだけを静的出力する。移動は通常のリンクに限定する。

## 実装メモ

- 記事の並び順はBLOG-002で確立した publishedAt 降順を使う。
- ページ1は / に統合し、2ページ目以降だけ /articles/page/{番号}/ を作る。
- 見た目は3列（Newer、現在位置、Older）の構造とし、詳細なCSSはBLOG-004で仕上げる。

## 設計判断

- 決定: 一覧本体とページ送りを共有する`ArticleList.astro`コンポーネントにまとめ、`/`を1ページ目、`/articles/page/[page]/`を2ページ目以降の静的ルートとした。ページ1の重複出力や一覧・移動UIの実装差を避け、必要なページだけ`getStaticPaths`から生成するためである。
- 決定: 共通処理で1ページ10件の切り出しとページ数を計算し、ページ送りは通常の`<a>`リンクで表現した。0件は0ページ、1〜10件は1ページとなり、動的ルートの対象を2ページ目から総ページ数までに限定できる。記事の並び順はBLOG-002の`publishedAt`降順を全件に適用してから切り出す。
