# 記事から元の一覧ページと閲覧位置へ戻れるようにする

## 問題

ブラウザーの「戻る」では通常、記事を開いた一覧ページとスクロール位置が復元される。一方、記事末尾の「← Articles」は固定で `/` へ移動するため、ページ送り先や一覧の途中から記事を開くと、戻った後に記事を探し直す必要がある。

## 意図

記事末尾の一覧リンクから、記事を開いた一覧ページと閲覧位置へ戻り、一覧の続きを見られるようにする。

## 受け入れ条件

- [x] 同じタブでトップまたはページ送り先の記事一覧から記事を開いた場合、記事末尾の一覧リンクで元の一覧ページとスクロール位置へ戻れる。
- [x] 同じタブでの一覧の戻り先に検索条件や検索結果の状態がある場合も、その条件と結果位置を復元できる。検索機能自体はこのIssueに含めない。
- [x] 記事へ直接アクセスした場合や一覧の戻り元を判定できない場合は、記事末尾の一覧リンクから `/` の先頭へ移動できる。
- [x] JavaScriptが利用できない場合も、記事末尾にキーボードで操作できる通常の一覧リンクがあり、一覧を表示できる。

- [x] 記事・一覧のリンクURLへ受け渡し用の識別子を追加しない。
- [x] 別タブでも通常リンクとして記事と一覧を表示できる。別タブでの検索状態・位置の復元は保証しない。

## 対象外

- 記事一覧の検索機能や検索結果表示（BLOG-019で扱う）
- 記事一覧のページ送り仕様や記事順序の変更
- ブラウザー標準の戻る・進む操作の変更
- 別タブ間での一覧URL・検索状態・閲覧位置の厳密な復元

## 品質境界

ユーザーの明示承認により、復元を保証する範囲は同じタブで一覧から記事を開いて戻る経路に限定する。この経路では一覧の完全URL・既存検索状態・閲覧位置を復元し、直接アクセスでは過去の保存情報を流用せず `/` への通常リンクを表示する。別タブ操作とJavaScript無効時は通常リンクとして一覧を表示できればよく、別タブの状態復元は保証しない。既存リンクURLへ識別子を付加せず、共有保存やタブ間の調整機構は設けない。

## 実装メモ

- 記事末尾の一覧リンクは `src/pages/articles/[slug].astro` にある。
- 着手時点でBLOG-019はclosedで、検索の開閉・入力値・全記事からの絞り込み・ハイライトが実装されていたため、既存検索の状態も復帰対象として検証した。検索機能自体は変更しない。
- 本番記事は10件でページ送り先が生成されないため、`/tmp/blog020-validation/fixture` の検証用コピーに11記事を追加し、2ページ目からの遷移を確認した。

## 設計判断

- 同じタブで記事リンクを操作したとき、一覧の完全URL（query/hashを含む）・記事URL・スクロール位置・既存検索の開閉状態と入力値をsessionStorageの1件の保存情報へ記録する。中クリックや修飾キー付きクリックでは保存しない。共有localStorage、URL識別子、有効期限と期限切れ情報の掃除は不要になったため撤去した。
- 記事URLと一覧のreferrerが保存情報に一致した場合だけ、記事末尾の通常リンクを元の一覧URLへ向ける。同じタブでこのリンクを操作したときに復帰要求をタブ内へ保存し、一覧では完全URLと記事のreferrerを照合して一度だけ取り出す。直接アクセスや不明な経路では保存情報を使わず、静的HTMLの `href="/"` を維持する。保存に失敗した場合は古い保存情報を削除し、誤った戻り先の流用を避ける。
- 一覧では既存検索の表示を再構成し、フォント読込後に位置を復元する。history APIやscrollRestorationには介入せず、ブラウザー標準の戻る・進むを維持する。履歴の `back()` に一覧リンクを置き換える方式は、直接アクセス時の固定リンクと一致判定済みの一覧URLを維持しにくいため採用しない。

## レビュー指摘

- 保証範囲と最小性（IMPL-1 / IMPL-2を含む）: 別タブの厳密な復元を暗黙に保証範囲へ追加し、共有保存・識別子・失効処理と復路の重複処理を増やしていた。ユーザーが同じタブでの復元だけを保証する範囲へ明示的に変更したため、別タブ復元の指摘は現在の品質境界外とし、共有保存と識別子を撤去してタブ内の保存と通常リンクに整理した。水平確認として同じタブでのURL・検索位置・キーボード操作・直接アクセス時の過去保存拒否・履歴・JavaScript無効・保存例外、および別タブの通常リンクを確認した。変更後の独立レビューで残存指摘なし。
