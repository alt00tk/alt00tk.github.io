# 記事から元の一覧ページと閲覧位置へ戻れるようにする

## 問題

ブラウザーの「戻る」では通常、記事を開いた一覧ページとスクロール位置が復元される。一方、記事末尾の「← Articles」は固定で `/` へ移動するため、ページ送り先や一覧の途中から記事を開くと、戻った後に記事を探し直す必要がある。

## 意図

記事末尾の一覧リンクから、記事を開いた一覧ページと閲覧位置へ戻り、一覧の続きを見られるようにする。

## 受け入れ条件

- [x] トップまたはページ送り先の記事一覧から記事を開いた場合、記事末尾の一覧リンクで元の一覧ページとスクロール位置へ戻れる。
- [x] 一覧の戻り先に検索条件や検索結果の状態がある場合も、その条件と結果位置を復元できる。検索機能自体はこのIssueに含めない。
- [x] 記事へ直接アクセスした場合や一覧の戻り元を判定できない場合は、記事末尾の一覧リンクから `/` の先頭へ移動できる。
- [x] JavaScriptが利用できない場合も、記事末尾にキーボードで操作できる通常の一覧リンクがあり、一覧を表示できる。

## 対象外

- 記事一覧の検索機能や検索結果表示（BLOG-019で扱う）
- 記事一覧のページ送り仕様や記事順序の変更
- ブラウザー標準の戻る・進む操作の変更

## 品質境界

記事一覧から記事へ移動した同一サイト内の経路で、一覧ページと閲覧位置を復元する。戻り元がない場合の直接アクセス経路では先頭の一覧を表示し、JavaScriptに依存しない通常リンクを保つ。

## 実装メモ

- 記事末尾の一覧リンクは `src/pages/articles/[slug].astro` にある。
- 着手時点でBLOG-019はclosedで、検索の開閉・入力値・全記事からの絞り込み・ハイライトが実装されていたため、既存検索の状態も復帰対象として検証した。検索機能自体は変更しない。
- 本番記事は10件でページ送り先が生成されないため、`/tmp/blog020-validation/fixture` の検証用コピーに11記事を追加し、2ページ目からの遷移を確認した。

## 設計判断

- 一覧から記事へのリンク操作時に、一覧の完全なURL（query/hashを含む）・スクロール位置・既存検索の開閉状態と入力値を、操作ごとのランダムな識別子に対応するlocalStorageへ保存する。記事URLには `list-origin` query、復路の一覧URLには `list-return` queryで識別子だけを付け、検索語や位置は含めない。保存情報は往路の保存から30分で失効し、次の往路保存時に期限切れ情報を削除する。30分という期間は受け入れ条件ではなく保存方式の制約であり、30分を超える記事閲覧では元の位置・検索状態を復元できない。保持期間の更新機構は追加しない。
- 記事のURLとreferrerが保存情報に一致する場合だけ一覧リンクの戻り先を変更する。中クリックで開かれるタブのsessionStorageは空になることを実ブラウザーで確認したため、一覧から記事への受け渡しには共有保存と識別子を用い、同一記事を複数タブに開いても保存情報を上書きしない。保存はpointerdown・click・contextmenuで行い、リンクの標準操作を妨げない。
- 往路で保存した情報と識別子を復路でも再利用し、記事の表示時に一覧への通常リンクを確定する。記事側の操作イベント、復路の再採番・再保存・期限切れ情報の掃除、移動先URLの重複保存は不要なため削除した。一覧側は保存情報から導いた復路URLと記事のreferrerを照合し、検索表示を再構成してフォント読込後にスクロール位置を復帰する。復元後は `history.replaceState` で現在の履歴項目のURLを元の一覧URLへ戻し、受け渡し用の識別子を除く。履歴項目数と戻る・進むの遷移順、scrollRestorationは変更しない。検索をURLへ移す方式は既存検索の契約を変えるため採用せず、現在の入力値と開閉状態だけを保持する。
- 保存情報が不正・失効、戻り元が不明、またはストレージが利用不可なら通常リンクへフォールバックする。共有保存が失敗した場合は識別子をリンクへ付けず、元のURLへの通常リンクを維持する。JavaScript無効時は静的HTMLの `href="/"` がそのまま操作できる。

## レビュー指摘

- IMPL-1 / IMPL-2（範囲内・対応）: 往路と復路の両方で新しいタブのsessionStorageが空になり、元タブへ保存するだけでは一覧URL・検索状態・位置を復元できなかった。往路の識別子と不変の共有保存情報を両方向で使う形へ統一し、同一記事を中クリックで2タブへ開いた後の検索なし430px・検索「Fixture」1350pxの独立復帰と、記事末尾リンクを中クリック／Ctrl+クリックした新規タブでの検索「Fixture」400pxの復帰を確認した。水平確認として元タブの検索変更後のタブ間分離、query/hashとURLエンコードの保持、識別子付き記事URLの直接アクセス時の `/` フォールバック、往復の保存例外、履歴項目数と標準の戻る・進む、JavaScript無効時の通常リンクを検証した。最小化後の独立再レビューでも解消を確認済み。
- 最小性（対応）: 復路でも再採番・再保存していたが、戻り先と検索状態は往路から変化しないため重複処理だった。往路の保存情報と識別子を再利用し、記事側では表示時に通常リンクを設定する形へ簡素化した。復路で保存内容が変わらないこと、保存への書込みが例外を投げても既存情報を使って復元できること、往復別タブと通常経路の回帰を確認した。往路保存から30分の失効制約を明記し、更新機構は導入しない。
