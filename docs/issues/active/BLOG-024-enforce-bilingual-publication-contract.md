# 日英同時公開と本文の記事間リンクをビルドで検査する

## 問題

日英ファイルの欠落や本文の参照先・言語の誤りを人の確認だけに任せると、日英同時公開の契約が破られ得る。

## 意図

日英ペアと記事間リンクの契約に違反した公開物の生成をビルドで止める。

## 受け入れ条件

- [x] npm run buildで全記事の日英slug集合の一致を検査し、どちらか片方しかない場合はビルドを非0で終了する。公開日時の不一致もエラーにする。
- [x] 本文の記事間リンクは日本語/articles/{slug}/、英語/en/articles/{slug}/のサイト内絶対パスに統一し、同じ言語の実在する記事を参照していることを検査する。
- [x] 通常形式と参照形式のMarkdownリンクを構文として解析する。コード内のリンク例を参照と誤判定しない。相対形式および同一サイトの完全URLによる記事参照も検知し、規定形式へ修正するよう報告する。
- [x] テンプレートが生成する言語切替・英語注釈の原文リンクは意図的な言語間参照として有効にする。外部サイトへのリンクと記事以外の参照を記事間リンクとして誤判定しない。
- [x] クエリ・フラグメント付き記事リンクでも記事の存在と言語を検査し、それらの有無で検査を回避できない。見出しIDの存在確認は行わない。
- [x] エラーには原因ファイル、対象slugまたはリンク先、違反理由を示す。欠落、日時不一致、リンク切れ、言語違い、形式違反を識別できる。
- [x] 日英欠落の両方向、リンクの各形式と正常・異常経路、コード例、外部リンクを検証し、正常な日英記事一式は既存の公開CIでビルドできる。
- [x] 日英同時公開、記事間リンク形式、原文更新時の日英確認、翻訳・レビュー後に同じ変更で公開する手順を関連する運用文書に記載する。

## 対象外

- 外部リンクのHTTP到達確認
- 見出しフラグメントの存在検証
- 本文リンクの自動修正
- 訳の意味やレビュー実施の自動判定
- 原文変更時の翻訳鮮度をハッシュで強制する仕組み

## 品質境界

ビルド入力全体の日英ペア、公開日時および本文の記事参照を契約として守る。同時公開は同じ配備成果物に両言語を含む意味とし、翻訳内容の妥当性は執筆・ChatGPTレビュー工程で担保する。

## 実装メモ

正規表現だけのMarkdown抽出を避け、実際のMarkdown解析・出力経路でリンクを扱う方法を検討する。導入前提は既存記事の日英対応が完了していること。mainへこの強制検査を早期導入しない。失敗時は前の配備を維持し、契約を満たす原稿へ修正する。ロールバックする場合は検査解除が公開契約を弱める点を記録する。

- このJP/EN対応では、一時的な `develop` を統合先とする。Issueブランチは最新の `develop` から作成し、Issue IDを含める。各Issueは承認後にclosedの記録を含めて `develop` へ `--no-ff` で統合する。通常運用のmain向け統合規則に対する、今回のユーザー承認済み例外である。
- mainでは日本語記事の執筆・公開を続ける。必要時および最終統合前にmainをdevelopへ取り込み、記事を失わない。Issueの完了はdevelopへの統合を意味し、本番配備済みとは扱わない。
- BLOG-021〜BLOG-024がすべてclosedとなり、最新mainを取り込んだ全記事の日英対応とビルドを再確認してから、人間の明示承認を得てdevelopをmainへ `--no-ff` で統合する。承認済みなのは今回の起案内容のmainへの直接コミットまでで、将来の統合・push承認を含まない。
- 本Issueは依存と記載の前提が満たされれば後続Issueなしでビルド・配備できる状態にする。実際の本番公開は全Issue完了後とし、main向けの既存配備workflowは維持する。

## 設計判断

- 既存loaderで全記事を読み込み、保存前に日英集合と公開日時の文字列一致を検査する。本文リンクはAstroのMarkdown描画結果をHTML構文として解析するため、通常形式と参照形式を同じ経路で扱い、コード例を除外できる。別のMarkdownパーサーを導入する案より描画結果との一致を優先した。
- テンプレート適用前の本文だけを検査し、言語切替と英語注釈の原文リンクは検査対象に含めない。URLをサイトoriginと記事URL基準で解決し、クエリとフラグメントを除いたパスで存在と言語を確認する。原稿名での相対参照も形式違反として扱い、修正先を示す。

- 記事URLの生成は既存の `articleUrl` に集約する。テスト入力は記事IDごとの本文と日時、および欠落記事のデータとして表し、ケース固有のmode文字列や分岐を持たせない。

## レビュー指摘

- 独立レビューで記事内見出し参照の誤判定と相対原稿リンクの検知漏れを確認し、範囲内として修正した。記事内参照を除外し、単一セグメントの実在slugと.md原稿参照を検知する。通常リンク、参照形式、相対URL、外部URLと一覧へのリンクを水平確認し、隔離ビルドの回帰ケースに残した。
- 実ビルドの異常系検証で、Astroのsite設定が文字列なのにURLとして扱い本文リンクが全て外部判定になる問題を確認した。loader境界でURLへ変換し、異常系が非0終了することを全ケースで確認した。独立レビューも型宣言と呼び出し経路を再確認した。
- review-orchestratorによる別コンテキストの独立レビュー最終結果は Looks acceptable、未解決指摘なし。基本5領域、公開CI、URL解決、テンプレート境界を確認した。独立担当の実ビルドはEPERMで実行できず、ビルド19ケースは実装担当が隔離環境で実行した。

- 追加整理の独立レビューは Looks acceptable、指摘なし。URL生成3箇所の同値性と19ケースの本文、日時、欠落対象、期待エラーを差分で照合し、検査規則の変更や不要な抽象化がないことを確認した。独立担当の比較スクリプト実行はEPERMで制約されたため、入力の直接照合と実装担当による実ビルド結果を証跡とする。
