# 記事本文の見出しにMarkdownの見出し記号を表示する

## 問題

ダークモードでは記事本文の見出しと通常の本文を見分けにくい。
Markdownの見出し記号はビルド時に取り除かれるため、公開ページには表示されない。

## 意図

記事本文の見出しにレベルに対応する `#` を表示し、見出しであることと階層を読み取りやすくする。

## 受け入れ条件

- [x] ビルド後の記事本文で、h1〜h6の先頭にレベルと同数の `#` が表示される。
- [x] ライト・ダークの両配色で記号が識別でき、320px幅でも記号による横はみ出しがない。
- [x] 記事タイトル・一覧見出しは対象に含めず、記事本文の見出しテキスト・意味構造・既存IDとアンカーを保つ。
- [x] ビルドとブラウザー確認を行い、独立レビューの結果を記録する。

## 対象外

- 見出しのフォントサイズや余白などの全面変更
- Markdown原文、記事タイトル、記事一覧の変更

## 品質境界

公開記事の本文見出しを対象とし、両配色・狭い画面・JavaScript無効時でも記号を表示する。
既存の見出し階層とアンカーを保ち、装飾記号は支援技術の見出し名に含めない。

## 実装メモ

- 記事本文は `.article-content` 内に静的生成され、配色はCSS変数で定義されている。
- JavaScriptの追加やMarkdown原文の変更を避けて表示できるか確認する。

## 設計判断

- 決定: `.article-content` 内のh1〜h6のCSS疑似要素に、レベルと同数の `#` を表示する。記号には既存の `--accent` 色と等幅フォントを使い、空の代替テキストを指定する。
- 理由・根拠: 静的HTMLの見出し名・階層・IDを変更せず、両配色とJavaScript無効時に同じ装飾を適用できる。Chromiumのアクセシビリティツリーでも見出し名に記号が入らないことを確認した。
- 却下した選択肢: Markdown変換処理で記号を挿入する案は、今回の表示上の変更に対して新しい変換処理を必要とするため採用しない。

## レビュー指摘

- 独立レビューで指摘なし。実装者とは別のエージェントが `review-orchestrator` に従い、CSS差分、記事テンプレート、配色定義、検証スクリプト、ダークモード320pxの画像を確認した。本文への限定、記号数、見出し名とIDの維持、配色と折り返しを確認し、追加対応や後続Issueは不要と判断した。

## 完了記録

- 変更: 記事本文のh1〜h6へ装飾記号を追加。記事タイトル、一覧、Markdown原文は変更しない。
- 検証: `npm run build` 成功。h1〜h6・長い日本語・見出し内リンク・コードを含む一時記事をビルドし、既存8記事・一覧・一時記事の計10ページについて、Chromiumでライト/ダーク × 320/1280pxの40通りを確認した。記号の数、コントラスト4.5以上、横はみ出しなし、記事タイトル/一覧への装飾なし、見出しのアクセシブル名維持、IDへの移動を確認した。JavaScript無効時にも両配色で全レベルの記号を確認した。一時記事は削除し、公開記事だけで再ビルドした。
- レビュー観点: 本文へのセレクター限定、階層とIDの維持、CSS疑似要素の空代替テキスト、狭幅での折り返し。独立レビュー実施済み、指摘なし。ブラウザー実測はChromiumのみで、Firefox/Safariと実機スクリーンリーダーは未確認。
- 状態: 実装・検証・独立レビュー完了。マージ承諾前のためactiveを維持する。
