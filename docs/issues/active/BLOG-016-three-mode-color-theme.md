# システム・ライト・ダークの配色を選べるようにする

## 問題

サイトの配色は明るいテーマに固定されており、利用者のOS設定や読書環境に合わせて暗い配色を選べない。

## 意図

システム設定に追従する初期状態と、利用者が保存できるライト・ダークの選択肢を全ページに提供する。

## 受け入れ条件

- [x] システム、ライト、ダークの3モードを選べる操作が全ページで利用できる。
- [x] 保存済みの選択がない場合はシステム設定に追従し、OSの配色設定変更も反映される。
- [x] ライトまたはダークを選択した場合、その選択がページ移動や再訪後も維持される。
- [x] 保存済みのモードがある場合、初回表示からその配色が適用され、明るい配色が一瞬表示される状態を避ける。
- [x] 選択操作はキーボードと支援技術で利用でき、保存機能が使えない場合もシステム設定で閲覧できる。
- [x] 背景、本文、補助文字、リンク、区切り線、コードブロックが各モードで読みやすく、フォーカス表示も識別できる。

## 対象外

- 利用者が色を自由に編集する機能
- テーマごとのレイアウトやフォント変更
- 外部サイトや埋め込みコンテンツの配色制御

## 品質境界

共通レイアウトを使うすべてのページと既存のコンテンツ要素で3モードを一貫して適用する。設定の有無や保存失敗によって白文字と白背景など判読不能な組み合わせを生じさせない。

## 実装メモ

- 現在の主要色は `src/styles/global.css` のCSSカスタムプロパティに集約されており、配色切替の基礎として利用できる。
- コードブロックは本文色と背景色を明示的に上書きし、トークン文字色も継承色へ揃えている。既存の単色表示を保つ場合も両テーマで確認する。
- 保存状態の適用は初回描画時のちらつきと、ブラウザー側保存機能を使えない場合の動作を含めて確認する。

## 設計判断

- 利用者が選ぶモードと実際の配色を分けた。システムモードは`data-theme`属性を付けず、CSSの`prefers-color-scheme`で描画するため、初期表示・OS設定変更・JavaScript無効時も同じ配色規則に従う。ライト・ダークのみ属性と`notes-theme`のlocalStorageへ記録し、システム選択時は保存値を削除する。実配色をJavaScriptで毎回計算してOS変更を監視する案より、状態と描画の同期箇所が少ない。
- 初回表示のちらつきを避けるため、共通レイアウトのhead先頭で同期インラインスクリプトを実行し、保存済みの有効なモードだけを属性へ反映する。本文下で初めて保存値を読む案は採用しなかった。不正値・読み込み例外はシステムへ戻し、書き込み例外は現在のページでの選択を維持して閲覧と再選択を可能にする。保存不能時の再訪は保存できた以前の値、読み込み不能ならシステムとなる。
- ユーザー指定の見た目に合わせ、共通ヘッダーを44px角の枠付きアイコンボタンと、その直下のコンパクトな3行メニューにした。標準select案から変更し、モニター・太陽・月のアイコン、日本語ラベル、選択行のチェック、ボタンの選択モードアイコンを組み合わせる。`aria-haspopup`・`aria-expanded`・`aria-controls`と`menu`・`menuitemradio`・`aria-checked`で開閉と単一選択状態を伝える。言語切替は追加しない。
- 独自メニューの操作責務は`ThemeMenu.astro`に閉じた。開いた直後は選択中の項目へフォーカスし、上下矢印・Home/Endはフォーカスだけを移動、Enter/Spaceで選択・保存して閉じる。Escと選択完了はボタンへ復帰し、外側クリック・Tab/Shift+Tab・外部へのフォーカス移動では移動先を保って閉じる。描画と保存の規則はheadとCSSの既存実装を使う。
- 背景・本文・補助文字・リンク・線をCSS変数で一緒に切り替え、既存コードブロックの単色表示を保った。ライトの補助文字も4.5:1以上へ調整し、境界線は3:1以上、フォーカスは各テーマのアクセント色と共通の輪郭を使用する。メニューはボタンの左端に揃え、320pxでも画面内に収まる184px幅にした。スクリプト起動まで操作部を非表示とし、JavaScript無効時はCSSでシステム配色を提供する。
