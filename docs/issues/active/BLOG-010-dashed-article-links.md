# 記事本文のリンク下線を破線にする

## 問題

記事詳細のMarkdown本文に含まれるリンクは、`src/styles/global.css`の`.article-content a`で実線の下線として表示されている。本文リンクの表現を破線にしたいという要望がある。

## 意図

記事本文のリンクを破線の下線で表示する。

## 受け入れ条件

- [x] 記事詳細のMarkdown本文に含まれるリンクの下線が破線で表示される。
- [x] 本文リンクの文字色による識別とキーボードフォーカス時の可視表示を保つ。
- [x] サイトヘッダー、記事一覧、ページ送り、記事末尾のナビゲーションなど、本文外のリンク表現は変更しない。

## 対象外

- リンク色、本文書体、余白、他の装飾の変更
- 記事本文以外にあるリンクのスタイル変更
- 外部リンクの開き方の変更

## 品質境界

対象は記事詳細の`.article-content`内にあるMarkdownリンクの下線表現に限る。リンクとして認識できる文字色と既存のキーボードフォーカス表示を保ち、本文外のリンクや記事レイアウトへ影響させない。

## 実装メモ

- `src/pages/articles/[slug].astro`の`<Content />`が生成する本文リンクを対象に、`src/styles/global.css`の既存本文リンク規則を確認する。
- 実際のMarkdownリンクを含む記事詳細を表示して、破線の見え方とフォーカス表示を確認する。

## 設計判断

- 既存の`.article-content a`へ`text-decoration-style: dashed`を追加し、下線の種類だけを変更した。本文に限定された既存セレクターを使うことで、リンク色、下線の位置、共通の`:focus-visible`表示、本文外リンクの規則を維持する。

## レビュー指摘

- 指摘なし。実装者とは別のサブエージェントが`review-orchestrator`でIssue、CSS差分、記事テンプレート、検証記録、フォーカス時の画面画像を確認した。本文への適用範囲と既存の文字色・フォーカス表示の維持を確認し、追加対応は不要と判断した。

## 完了記録

- 変更: `src/styles/global.css`の本文リンク規則へ`text-decoration-style: dashed`を追加した。
- 検証: `npm run build`成功（7ページ生成）。ローカルプレビューの`/articles/ai-and-intuition/`をChromiumで表示し、既存Markdownリンクの計算済みスタイルが`underline` / `dashed`、文字色が既存のアクセント色`rgb(85, 106, 93)`であることを確認した。Tabキーで本文リンクへ移動し、`:focus-visible`と`2px solid`の輪郭を確認した。画面画像でも破線と輪郭を確認した。
- 検証: サイトヘッダー、記事末尾ナビゲーション、トップページの記事一覧リンクはChromiumで下線なしのままであることを確認した。ページ送りは現行の6記事ではリンクが生成されないため実表示の確認対象なし。CSS差分が本文リンク規則の1行だけであり、本文外とページ送りの規則を変更していないことを確認した。
- レビュー観点: 本文リンクだけに破線が適用され、文字色とキーボードフォーカス表示が維持されていること。独立レビュー済み、指摘なし。レビューではビルドとブラウザ操作を再実行せず、実装者の記録と画面画像を確認した。
