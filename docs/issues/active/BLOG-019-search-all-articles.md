# 記事一覧をタイトル・説明文で全記事検索できるようにする

## 問題

記事一覧にはタイトルと説明文が表示されるが、キーワードで絞り込む操作はない。現在は公開記事が8件で1ページに収まるものの、一覧は1ページ10件で、記事が増えるとページをまたいで探す必要がある。

## 意図

記事一覧から、タイトルまたは説明文を手掛かりに全公開記事を検索できるようにする。

## 受け入れ条件

- [x] トップとページ送り先の記事一覧に検索操作があり、入力した文字列がタイトルまたは説明文に含まれる公開記事を表示する。
- [x] 検索対象はページ分割に依存せず、全公開記事を含む。
- [x] 検索フォームは初期状態で非表示とし、ヘッダーのテーマ切替左にある検索アイコンから開閉できる。
- [x] 展開時は入力欄へフォーカスし、再クリックまたはEscapeで閉じると検索語を消去して元ページの一覧とページ送りへ戻り、検索アイコンへフォーカスする。
- [x] 展開中は空入力なら全公開記事を表示し、検索語がある場合だけ結果件数を表示する。専用のクリア操作ではフォームを閉じず、全公開記事へ戻る。
- [x] 該当記事がない場合は、0件であることと該当記事がないことを簡潔に表示する。
- [x] タイトルと説明文の一致箇所をすべてmarkで強調し、英字の大小を無視する判定を保つ。語の変更、クリア、終了で強調を更新し、記事データを変えず安全に描画する。
- [x] 強調色はライトで #e7e5c4、ダークで #4c5036 とし、OS設定と手動選択に追随する。
- [x] PCとモバイルで既存のヘッダー、記事配置、文字組みを保ち、閉じたフォームは余白とフォーカス対象を残さない。検索のラベル、開閉状態、件数通知、テーマ切替が機能する。
- [x] 検索結果の記事タイトルから、既存の通常リンクで記事詳細へ移動できる。
- [x] 検索入力と結果の操作・移動をキーボードで行える。
- [x] JavaScriptが利用できない場合も、検索前の既存記事一覧とページ送りで記事を閲覧できる。

## 対象外

- 記事本文の全文検索
- 外部検索サービスや検索用サーバーの導入
- 記事データ、公開順、既存ページ送り件数の変更

## 品質境界

検索対象はビルド時点の全公開記事とし、ページ分割後も記事を取りこぼさず検索できることを対象とする。検索結果の移動は既存の記事詳細URLを使い、JavaScriptが利用できない場合の一覧閲覧を保つ。

## 実装メモ

- 対象箇所は `src/components/ArticleList.astro`、`src/layouts/BaseLayout.astro`、`src/pages/index.astro`、`src/pages/articles/page/[page].astro`、`src/styles/global.css`。
- 起案時から記事が増え、実装時点の公開記事は10件だった。
  実記事に加え、21件で3ページになる隔離した一時環境でページをまたぐ検索を確認した。

## 設計判断

- 決定: 一覧の各ルートから公開順に並べた全公開記事を共有コンポーネントへ渡し、既存の10件単位の切り出しで初期表示する記事を決める。
  各記事は通常リンク付きのHTMLとして一度だけ出力し、現在ページに属さない記事にはサーバー側で `hidden` を付ける。
  検索用JSONと結果描画を別に持つ案に比べ、タイトル、説明文、日付、リンクの出力を共通化でき、JavaScriptが動かなくても元ページの表示を保てるため採用した。
- 決定: 検索開始はヘッダーのテーマ切替左にあるボタンとし、一覧ページだけがレイアウトの `searchable` を有効にする。
  フォームと起動ボタンは初期HTMLで非表示にし、起動ボタンはイベント登録後に表示する。
  閉じたフォームはフォーカス対象と余白を残さず、JavaScript不動時は従来の記事閲覧を保つ。
- 決定: 検索は閉状態と展開状態を区別し、展開中は空入力でも全公開記事を表示してページ送りを隠す。
  専用クリアではフォームを保って入力へ戻り、ボタンの再クリックまたはEscapeで閉じたときに語を消去して元ページの一覧とページ送りへ戻す。
  これは今回の利用者指定による変更であり、当初の「消去で通常一覧へ戻す」から更新した。
- 決定: 既存の小文字化とincludesによるタイトルまたは説明文の部分一致を保ち、同じ小文字化文字列上の一致位置を原文へ対応付けてmarkを作る。
  İのように小文字化で文字数が増える場合と、重なり合う一致も原文上の範囲へ戻して強調する。
  原文を保持し、テキストノードとmarkだけで置き換えるため、検索語や記事のHTML風文字列をHTMLとして解釈しない。
- 決定: 件数通知は検索語があるときの短い `role="status"` だけに限定し、同じメッセージの再代入を避ける。
  強調色は既存のOS設定と手動選択のCSS変数へ統合し、既存の配色切替を再利用する。
  フォーカスは展開時に入力、終了時に起動ボタンへ移す。

  新規ライブラリや不要な旧処理はなく、今回の追加条件と既存の閲覧経路を満たすことを確認した。
