# 記事一覧と詳細ページを静的生成する

## 問題

記事の入力契約が整っても、Markdownから記事一覧や個別記事へ移動できるページがなければブログとして閲覧できない。

## 意図

有効なMarkdown記事から、記事一覧と記事詳細を静的に生成し、記事情報を一貫して表示する。

## 受け入れ条件

- [ ] / に記事一覧を生成し、各行に東京時間の YYYY.MM.DD、詳細ページへの通常リンクとなる記事タイトル、descriptionを表示する。
- [ ] /articles/{slug}/ に記事詳細を生成し、日付、titleをh1見出しとして、descriptionを導入文として、Markdown本文をその後に表示する。
- [ ] 一覧と詳細の順序は publishedAt の完全なタイムスタンプ降順で決まり、同じ日の記事も時刻で正しく並ぶ。slugによる同時刻の追加ソートを行わない。
- [ ] 一覧と詳細の日付は同じ publishedAt を Asia/Tokyo で YYYY.MM.DD に変換して表示する。
- [ ] 一覧ページの文書タイトルは notes とし、マーケティング用の文言を追加しない。詳細ページの文書タイトルは「記事タイトル — notes」、meta descriptionは記事のdescriptionとする。
- [ ] 一覧・詳細の文書言語は日本語になる。
- [ ] 記事末尾に ← Articles を置き、常に / への通常リンクとして動作する。
- [ ] 記事本文で段落、##・###見出し、順序なし・ありリスト、引用、リンク、強調、インラインコード、フェンス付きコードブロックを表示できる。
- [ ] 一覧から詳細への移動と記事末尾からの戻りがJavaScript無効時にも動作し、クライアント側ルーターや記事データストアを必要としない。

## 対象外

- 1ページ10件への制限とページ送り（BLOG-003で扱う）
- 試作HTMLに基づく最終的なレイアウト、色、余白、レスポンシブ調整（BLOG-004で扱う）
- Aboutページ、タグ、カテゴリ、検索、関連記事、画像、MDX、記事本文のraw HTMLやテーブル対応
- 記事一覧の空状態に対する仕様外の案内文追加

## 品質境界

ビルド時点で存在する有効な記事を漏れなく一覧と詳細へ反映し、一覧・詳細・戻りリンクを静的HTMLとして提供する。記事の公開状態を追加せず、本文のdescriptionを重複表示しない。

## 実装メモ

- URLの末尾スラッシュを保ち、slugはBLOG-001のファイル名契約に従う。
- 引継ぎ資料と同梱プロトタイプは .local/blog-mvp-codex-handoff.tar.gz 内にある。
- ページ枠と見た目の仕上げはBLOG-004に残し、このIssueではページの意味と遷移、表示データを確認できる最小限の構造を実装する。
