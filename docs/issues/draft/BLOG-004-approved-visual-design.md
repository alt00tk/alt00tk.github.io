# 承認済みプロトタイプの見た目を実装する

## 問題

記事ページの基本動作ができても、承認済みプロトタイプの幅、文字、余白、ヘッダー、フッターを再現しなければ、決定済みのブログデザインにならない。

## 意図

引継ぎ資料に同梱された試作HTMLを見た目の基準として、一覧、詳細、ページ送りの共通スタイルとレスポンシブ表示を実装する。

## 受け入れ条件

- [ ] .local/blog-mvp-codex-handoff.tar.gz に含まれる blog-mvp-interactive-prototype-v4.html と引継ぎ資料の意図に沿い、最小限で読みやすく落ち着いた表示になる。
- [ ] 背景は #f7f7f3、文字は #1f2421、補助文字は #7a827d、アクセントは #556a5d とする。区切り線は文字色の12%を透明色へ混ぜる。サイト最大幅は900px、記事最大幅は825pxとする。
- [ ] Zen Maru Gothicを主フォントとし、指定された400・500・700のウェイトを使う。基準文字サイズは 1rem、行高は 1.95、字間は 0.015em とする。
- [ ] ヘッダーは左寄せの notes のみを表示して / へリンクし、下部に区切り線を置く。
- [ ] フッターは上部に区切り線を置き、「© 2026 notes」を表示する。短いページでは画面下部に位置し、長いページでは本文の後に続く。固定配置を使わない。
- [ ] 記事一覧はデスクトップで日付列と記事内容列を使い、モバイルでは日付をタイトル・descriptionの上に積む。記事ごとの区切り線は置かない。一覧・詳細の日付文字サイズは本文と同じ 1rem とする。
- [ ] 記事詳細は日付、タイトル、description、区切り線、本文の順にし、本文の後に十分な余白を設けて ← Articles を置く。戻るリンク専用の区切り線を追加しない。
- [ ] ページ送りは「Newer / 現在位置 / Older」の3列構成を保ち、番号リンク列やカード装飾を追加しない。
- [ ] 幅640px前後を境に、小画面では横余白を減らし、承認済みのモバイル配置になる。実装結果を広い画面と小さい画面で確認する。
- [ ] カード、影、グラデーション、イラスト、バッジ、チップ、装飾アイコン、余分なナビゲーションを追加しない。

## 対象外

- Issue 002・003で扱う記事データ処理、URL、ページ送り条件の変更
- Aboutページなど新しい画面・機能の追加
- favicon（Astroの初期生成で必須の場合を除く）、独自404、分析、OGP画像生成
- JavaScriptを使ったレイアウトや遷移

## 品質境界

一覧、詳細、ページ送りを共通の静的ページ構造上で一貫して表示し、プロトタイプの余白と読みやすさを保つ。追加の装飾や画面は作らない。

## 実装メモ

- ビジュアル参照の正本は .local/blog-mvp-codex-handoff.tar.gz 内の blog-mvp-codex-handoff/blog-mvp-interactive-prototype-v4.html。引継ぎ資料の明示的な上書きがある箇所は資料を優先する。
- ページ全体を縦方向のflex構造にし、最小高さを 100dvh、本文領域を伸長可能にする。
- 記事タイトルは clamp(1.45rem, 3vw, 1.8rem)、行高は 1.65、ウェイトは700を基準にする。
