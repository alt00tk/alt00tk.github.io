# ヘッダーにGitHubリポジトリへのリンクを追加する

## 問題

サイトのヘッダーには「notes」へのリンクだけがあり、記事の原稿やサイトの実装を管理する公開GitHubリポジトリへ、サイトから移動する手段がない。

## 意図

すべてのページのヘッダーから、このサイトのGitHubリポジトリへ移動できるようにする。

## 受け入れ条件

- [x] 生成された全ページのヘッダーに `https://github.com/alt00tk/alt00tk.github.io` へのリンクがある。
- [x] リンクはアイコンで示され、支援技術から目的が分かり、キーボードでも操作できる。
- [x] デスクトップと狭い画面の両方で、サイト名リンクや本文の閲覧を妨げない。
- [x] 外部リンクの開き方が明確で、別タブで開く場合は安全な関係属性を持つ。

## 対象外

- GitHubユーザープロフィール、他のSNSや連絡先へのリンク
- ヘッダー全体の再設計

## 品質境界

共通レイアウトを使うトップ、記事一覧、記事詳細のすべてで、同一の公開リポジトリへ移動できることを対象とする。既存のサイト内リンク、ページレイアウト、キーボード操作を損なわない。

## 実装メモ

- 共通ヘッダーは `src/layouts/BaseLayout.astro` にある。
- 記事本文の外部リンク処理は本文内だけを対象にするため、ヘッダーリンクの開き方は独立して確認する。

## 設計判断

- 全ページが使用する `BaseLayout.astro` のヘッダーへ、インラインSVGを持つ通常のリンクを追加した。アイコンライブラリーやブラウザースクリプトを追加せず、リンク先と開き方を生成HTMLに確定する。
- リポジトリは記事の閲覧位置を維持できる別タブで開く。同じタブへの遷移も可能だが、記事本文の外部リンクと揃う別タブを採用し、`aria-label` と `title` で開き方を伝え、`rel="noopener noreferrer"` で元ページへのアクセスを防ぐ。SVGは装飾として支援技術から隠す。
- ヘッダー内をflexで左右配置し、アイコンの操作領域を44px四方にした。既存のサイト幅・ヘッダー余白・フォーカス表示を使い、320pxと1280pxの実ブラウザーでサイト名との非重複と本文への非干渉を確認した。

## レビュー指摘

- 指摘なし。実装担当とは別のエージェントが、差分、共通レイアウトの呼び出し元、既存スタイル、検証スクリプト、320px・1280pxの画像を独立に確認した。5つの基本レビュー観点に加え、支援技術向け名称、キーボード操作、狭い画面の配置、別タブの安全性を確認し、Blocking・Warningともに0件だった。ビルドとブラウザー操作の再実行、実機の支援技術、GitHub側の応答はレビュー対象外とした。
