# 文字サイズと記事幅を調整しページ間の横位置を安定させる

## 問題

ローカルプレビューでBLOG-006の文字サイズが大きく感じられた。
記事タイトルは640pxに制限され、記事領域の右側に余裕があっても折り返されていた。
短い一覧と長い記事でスクロールバーの有無が異なり、共通ヘッダーのnotesの左端が移動していた。

## 意図

ローカルで調整した文字サイズと記事幅を正式に反映し、ページ間の横位置を安定させる。

## 受け入れ条件

- [x] サイト全体の文字サイズがBLOG-006時点の0.9倍になり、可変サイズと小画面のタイトル指定も同じ倍率になる。
- [x] 記事領域はサイト領域の95%幅になり、タイトルは記事領域と同じ幅まで使用できる。
- [x] スクロールバーがない一覧とスクロールバーがある記事でも、共通ヘッダーのnotesの左端が揃う。短い一覧にスクロールバーを強制表示しない。
- [x] 正式なCSSが、ユーザーがローカルプレビューで確認した未コミットCSSと一致する。

## 対象外

- 記事内容、ページ構造、配備設定の変更
- src/content/blog/.gitkeepの削除
- 色、サイト最大幅、行高などその他のデザイン変更

## 品質境界

既存の一覧と記事ページの共通CSSだけを調整する。ユーザーのChromeで確認されたページ間の横位置を保ち、記事データとその他の未コミット変更を統合対象へ含めない。

## 実装メモ

- ユーザーは日を改めながらローカルプレビューで調整し、変更をまとめたIssue化とmainへのマージを依頼した。
- スクロールバー対策後、ユーザーはnotesの左端が揃い、一覧にはスクロールバーが表示されないことを確認した。

## 設計判断

- 各文字サイズを0.9倍にし、親文字サイズに追従するコードのem指定は維持した。ルートの文字サイズ変更によってrem指定の余白も変える案を避け、文字サイズを局所的に調整した。
- 記事幅を固定825pxからサイト領域の95%へ変更し、タイトルのmax-widthを100%にした。記事枠に余裕があってもタイトルが640pxで折り返される制限を取り除いた。
- htmlにscrollbar-gutter: stableを指定した。常時スクロールバーを表示する案では短い一覧にもバーが出るため、領域だけを確保する方法を採用した。

## レビュー指摘

- 指摘なし。CSS差分をレビューし、文字サイズの倍率、記事とタイトルの幅、スクロールバー用領域の指定が受け入れ条件と一致することを確認した。記事データとページ構造に変更はない。

## 完了記録

- 変更: 共通CSSで文字サイズ12箇所を0.9倍にし、記事幅を95%、タイトルのmax-widthを100%にした。htmlへscrollbar-gutter: stableを追加した。
- 検証: ユーザーのローカルプレビューで表示を確認済み。Chromeで記事だけにスクロールバーが出る状態でもnotesの左端が揃うことをユーザーが確認した。git diff --checkで問題がなく、cmpで専用worktreeのCSSが承認された作業ツリーのCSSと完全一致することを確認した。
- レビュー観点: 文字サイズの倍率、記事幅とタイトル幅、一覧と記事間の横位置を確認する。プレビューの画面確認はユーザーの報告を根拠とし、追加のブラウザー検証は実施していない。
