# 記事本文の外部リンクを別タブで開く

## 問題

記事本文のMarkdownリンクは現在のタブで遷移する。たとえば`src/content/blog/ai-and-intuition.md`には外部のDOIリンクがあり、読書中に参照先を開くと元の記事から離れてしまう。

## 意図

記事を読んでいるタブと位置を保ったまま、記事本文の外部リンクを別タブで開けるようにする。

## 受け入れ条件

- [x] 記事本文にあるサイト外のHTTP(S)リンクを開くと別の閲覧コンテキストが開き、元の記事と読書位置が保たれる。
- [x] 相対URLまたはサイトと同一originのリンク、および記事末尾の`← Articles`は現在のタブで開く。
- [x] 別コンテキストで開くリンクから元のページを操作できないようにし、リンク先URLと表示名は維持する。

## 対象外

- 記事一覧、サイトヘッダー、ページ送りなど本文外のリンク
- `mailto:`などHTTP(S)以外のリンク形式
- 記事内容や外部リンク先の変更

## 品質境界

対象は記事詳細のMarkdown本文に出力されるHTTP(S)リンクであり、サイトの現在のoriginと異なるリンクを外部リンクとして扱う。同一サイト内の遷移は同じタブで動作させ、別コンテキストから元ページを操作できない状態を保つ。

## 実装メモ

- 対象経路は`src/pages/articles/[slug].astro`の`<Content />`が描画する本文リンクである。記事末尾のナビゲーションやレイアウト内のリンクは本文に含まれない。
- 現在の記事本文にあるDOIリンクを使い、外部リンクと同一サイト内リンクの開き方を確認する。

## 設計判断

- 記事詳細のブラウザースクリプトで`.article-content a[href]`を処理し、アンカーの`protocol`と`origin`を実際の`window.location.origin`と比較する。ビルド時に`site`と比較する案も検討したが、localhostや別originで閲覧したときも現在のoriginを基準に判定する品質境界を満たすため、実行時の判定を採用した。
- 外部HTTP(S)リンクへ`target="_blank"`と`rel="noopener"`を付与する。クリックやスクロールを独自に制御せずブラウザーのリンク動作へ委ね、`relList.add`で既存のrelトークンを保持し、hrefと表示名は変更しない。JavaScriptが無効な環境では従来のリンク動作となる。

## レビュー指摘

- 指摘なし。実装担当とは別のエージェントが、差分・生成HTML・検証用スクリプトを独立に確認し、品質境界と受け入れ条件の証拠を妥当と判断した。

- 検証: `npm run build`成功（7ページ生成）。`node /tmp/blog011-check.mjs`成功。生成HTMLの実際のDOIリンク2件と、HTTP・HTTPS・プロトコル相対・相対・アンカー・同一origin・異なるport・mailto・telを含む計24ケースを本番originとlocalhostで生成JavaScriptに通し、target/relとhref・表示名・既存relの保持を確認した。記事末尾・ヘッダーのリンクが無変更で、一覧ページへ処理が出力されないことも確認した。
